# Індекси та продуктивність

## Типи індексів

### B-tree (за замовчуванням)
Для операцій: `=`, `>`, `<`, `>=`, `<=`, `BETWEEN`, `IN`, `LIKE` (не з % на початку), `ORDER BY`
```sql
CREATE INDEX idx_users_email ON users(email);
CREATE UNIQUE INDEX idx_users_email_unique ON users(email);
```

### Hash
Тільки для операції `=`
```sql
CREATE INDEX idx_users_email_hash ON users USING HASH (email);
```

### GiST
Для геометричних даних, повнотекстового пошуку
```sql
CREATE INDEX idx_articles_content ON articles USING GIST (to_tsvector('ukrainian', content));
```

### GIN
Для JSONB, масивів, повнотекстового пошуку (швидше за GiST для пошуку)
```sql
CREATE INDEX idx_users_tags ON users USING GIN (tags);
CREATE INDEX idx_products_meta ON products USING GIN (metadata);
```

### BRIN
Для дуже великих таблиць з фізично впорядкованими даними
```sql
CREATE INDEX idx_orders_created ON orders USING BRIN (created_at);
```

## EXPLAIN ANALYZE

```sql
EXPLAIN ANALYZE SELECT * FROM users WHERE email = 'test@example.com';
```

## Коли індекси НЕ працюють

- `LIKE '%text'` — пошук з % на початку (але працює `trigram`)
- Функція на колонці: `WHERE UPPER(name) = 'IVAN'` — потрібен функціональний індекс
- Невідповідність типів
