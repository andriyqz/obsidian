# Транзакції та ізоляція

## Транзакції

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;  -- або ROLLBACK;

-- Savepoint (точка збереження)
BEGIN;
INSERT INTO logs VALUES ('start');
SAVEPOINT sp1;
INSERT INTO logs VALUES ('step1');
ROLLBACK TO sp1;  -- відкотити до savepoint
COMMIT;           -- фіксує тільки перший INSERT
```

## Рівні ізоляції (SQL стандарт)

| Рівень                   | Dirty Read | Non-repeatable Read | Phantom Read |
|--------------------------|:----------:|:-------------------:|:------------:|
| READ UNCOMMITTED         | ❌ (PG = RC)| ❌                  | ❌           |
| READ COMMITTED (default) | ✅         | ❌                  | ❌           |
| REPEATABLE READ          | ✅         | ✅                  | ❌           |
| SERIALIZABLE             | ✅         | ✅                  | ✅           |

> PostgreSQL фактично не підтримує READ UNCOMMITTED — він працює як READ COMMITTED.

```sql
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

## Аномалії

- **Dirty Read** — читання незафіксованих даних
- **Non-repeatable Read** — різні результати при повторному читанні того ж рядка
- **Phantom Read** — нові рядки з'являються при повторному запиті

## MVCC (Multi-Version Concurrency Control)

PostgreSQL створює **копії рядків** (версії) при зміні. Кожна транзакція бачить "знімок" даних на момент свого початку. Читання ніколи не блокує запис і навпаки.
